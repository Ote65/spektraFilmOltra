> 文档用途：给 iOS 开发者逐文件、逐符号地定位 macOS 已实现的视频显影代码，并标注移植时必须保留 / 必须改写 / 必须避坑的点。
> 仓库：`SpektrafilmSwift-ios`　分支基线：当前 `iOS`（macOS 视频台代码以未提交文件形式存在于该分支工作区）
> 代码快照日期：2026-11-18　方案基准：`docs/feature-plan-video-develop.md`
> 配套文档：`docs/视频显影_iOS架构清单与四表_20261118.md`（iOS 侧架构清单 / 模块索引 / 关联表 / 映射表）
> 本文**不含代码改动**，只做位置引导与标注。文中行号对应上述快照，改动后请以符号名为准重新定位。

## 0. 怎么用这份文档

1. **核心层可直接复用**：`Sources/SpektraCore/Video/` 下 11 个文件是跨平台的（Foundation / AVFoundation / Metal / CoreVideo），"一套核心两端复用"是方案第 1 原则。iOS 工程 `project.yml` 已把整个 `Sources/SpektraCore` 纳入编译，**这些文件加入后无需登记 pbxproj 即可编进 iOS**（若用工程文件而非 xcodegen，则需手动 Add Files）。
2. **壳层必须重写**：macOS 壳层在 `SpektraSkin`（AppKit / NSImage / NSOpenPanel / NSSavePanel），iOS 壳层在 `SpektraMobile`（UIKit / UIImage / PhotosPicker / 相册），不能照搬。
3. **标注优先级**：`[保留]`＝逐字照搬否则出错色/死锁；`[改写]`＝平台 API 需替换；`[iOS 特有]`＝macOS 没有、iOS 必须补；`[踩坑]`＝实测踩过的坑，踩了会出现雪花噪点 / 卡死 / 串帧。

## 2. 分层架构与数据流

```
┌─ 壳层（平台相关，需重写）───────────────────────────────┐
│  VideoHost (S1)  ──@Published──▶  VideoView (S2)          │  macOS
│  MVideoSession    ──@Published──▶  MVideoScreen           │  iOS（待建）
└──────────────────────┬───────────────────────────────────┘
                       │ 调用
┌─ 共享核心（跨平台，直接复用）────────────────────────────┐
│  VideoExporter (C9) ──▶ VideoFramePipeline (C8)            │
│        │                    ├─ probe / referenceFrame       │
│        │                    ├─ measureEV (复用 AutoExposure)│
│        │                    ├─ prepareSetup / frameUniforms │
│        │                    └─ developStill / export        │
│        │                              │                     │
│        │        ┌─────────────────────┼─────────────────┐   │
│        │        ▼                     ▼                 ▼   │
│        │  VideoLUTBaker(C4)   VideoGrainModel(C5)  VideoColorIO(C2)
│        │        │                     │                     │
│        │  VideoLUTPayload(C3)   VideoShaders(C6) ─▶ VideoMetalRenderer(C7)
│        │                                                   │
│        └──▶ VideoAudioMuxer (C10)                          │
│  VideoProjectStore (C11)  ── 工程索引（独立于照片库）       │
└───────────────────────────────────────────────────────────┘
                       │ 复用（不改）
┌─ 既有照片核心 ────────────────────────────────────────────┐
│  PreviewLUTService（烘焙 + lookupInPlace + measureAutoEV） │
│  PhotoEdit / PhotoEdit.runtimeParams()                     │
│  ColorMath.rgbToRGB（矩阵来源） / ImageRGB / ImageBridge    │
└───────────────────────────────────────────────────────────┘
```

**单帧显影链**（UI 暂停时触发，播放中不跑）：
`AVAssetImageGenerator 抽帧 → CGImage → StillBridge 画进 BGRA CVPixelBuffer → VideoMetalRenderer.render（5 pass）→ CGImage → NSImage/UIImage 叠在播放器上`

**全片导出链**（点「开始渲染」后触发）：
`VideoExporter.export → prepareSetup（烘 LUT 一次）→ pipeline.export（Reader 逐帧 → render → Writer 无声 .mov）→ VideoAudioMuxer.mux（音轨直通）→ 成品`

### 3.6 `VideoShaders.swift`（C6）

| kernel / 符号 | 行号 | 说明 |
|---|---|---|
| `source` | 11–273 | 整段 MSL 字符串，运行时 `makeLibrary(source:)` |
| `lutSample` | 17–55 | 三线性查表，最大分量优先分解；与 CPU `lookupInPlace` 顺序一致；**不 clamp 输出** |
| `t1Shaped` | 57–60 | log2 shaper |
| `displayToLinearProPhoto` | 63–71 | EOTF + 矩阵；**列向量乘** `m0*lin.x+m1*lin.y+m2*lin.z` |
| `hashU32/hash21/valueNoise` | 77–95 | 整数位混合哈希 + 值噪声 |
| `struct FrameParams` | 97–126 | 与 Swift 侧同布局（含显式 pad） |
| `kernel develop` | 128–171 | 主链：EOTF→ProPhoto→t1→EV→t2→密度域颗粒→t3→印相EV→t4 |
| `kernel bloomDownsample/H/V` | 173–226 | 半分辨率光晕/柔光金字塔 |
| `kernel composite` | 239–272 | USM + bloom 合成 + Rec.709 OETF → BGRA8 |

- `[保留]` `[踩坑]` **矩阵乘法**（L68–70）：m0/m1/m2 是列，必须 `M*v = col0*v.x+col1*v.y+col2*v.z`；用 `dot(col,v)` 会通道串位（maxΔ 从 1 飙到 95）。
- `[保留]` `[踩坑]` **整数哈希**（L74–84）：帧种子是 uint32（几十亿），先转 float 再 `fract` 在 2³¹ 量级 ULP≈256，只剩 1/256 粗台阶 → 颗粒变静态贴层。必须用整数位混合。
- `[标注]` MSL 里 seed 字面量用 `1u`（无符号），不要写 `1.0f`。

## 7. 验收门禁（iOS 移植后照跑）

- **M0 颜色**：同一 8-bit 帧 GPU vs `VideoLUTPayload.predictLinear` 对拍 36 样本，`maxΔ≤1/255`、`meanΔ≤0.2/255`（macOS 实测 maxΔ=1、meanΔ=0.194）。
- **颗粒**：相邻帧 ≥90% 像素不同；同帧重复一致；24 帧连续播放无静态图案。
- **导出**：24 帧 1080p 可播放、时长/尺寸/音轨正确；取消 200ms 内响应。
- **性能**：24 帧 iOS ≤3s（目标），60 秒端到端 ≤60s；5 分钟内存 <300MB 无逐帧增长。
- **参考**：macOS 实测 24 帧 1080p30 导出 0.49–0.56s；单帧颗粒 amplitude≈0.0129（grain 100%）。
